# 4D.7C product catalog

The existing connected product model gains one canonical `unit` column: trimmed
text of 1–40 characters, NOT NULL, default `Unidad`. Category remains nullable
for legacy database rows; connected Add/Edit requires an explicit category or
an explicit new-category name. Price stays in integer minor units. Images have
no connected controls or storage architecture.

Migration `202610120003_product_unit.sql` replaces only the existing product
read projection and cafeteria command definition, preserving 4D.6 authority,
locks, request fingerprints and revalidation. Unit updates share the existing
product version increment, row lock and transaction. Final command audit records
product ID and unit alongside existing real/effective attribution. Legacy pending
payloads without unit remain untransformed and leave the stored unit unchanged.

The existing editor now opens in the shared native dialog. A portal keeps the
modal outside the provider's disabled fieldset; explicit mutation state disables
its form while its close and exact pending-request recovery remain reachable.
Drafts carry their original authoritative version, not a later refreshed version.
