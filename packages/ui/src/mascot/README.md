# PIKAS mascot in the apps

Shared primitives for the PIKAS mascot system. Design source of truth: `docs/pikas-mascot-system/`
(brief, proposal, previews, generator scripts). Shipped copy: `packages/ui/assets/mascot/`, kept identical by
`npm run mascot:sync -w @pikas/ui` and verified by `npm run mascot:check -w @pikas/ui` (exit 1 on any drift).
Nothing is copied at build time; `src/mascot/assets.generated.ts` is regenerated by the sync and committed.

## API (`@pikas/ui/mascot`)

- `<PikasMascot id size animated meaningful alt className />` — any catalog asset by manifest id. Decorative by
  default (`alt=""` + `aria-hidden`); `meaningful` uses the manifest's Spanish alt text. Dev-only warnings for
  unknown ids and sizes outside the asset's `sizePx`. Never below 24 px. One animated mascot per screen.
- `<PikasLoader label slowLabel size />` — LOAD-01: nothing for 1 s, the loop until 10 s, then visible text.
  `role="status"` text is always present.
- `PikasSessionCountdown` — Phase 2 (ATT-01, inline SVG, `--countdown`).
- `mascotManifest`, `mascotAssets`, `mascotSizeRange`, `mascotAsset(id)`.

Rules that affect code (from the brief): the mascot explains a state or a next step, never decorates the middle
of a task; **no mascot** on declined payments, failed transfers, insufficient balance, suspicious activity,
permission errors, data loss or security failures; never beside amounts, confirmations or irreversible actions;
cap sets (onboarding, cafetería, POS) and hatless sets are never mixed on one screen; status words, errors and
colours are never replaced by the picture; motion already stops under `prefers-reduced-motion`.

## Adding a surface

1. Pick the asset id from `manifest.json` (`use`, `contexts`, `never`, `sizePx`).
2. Keep the heading/body text saying what the state is; the mascot is decorative.
3. Add the row above and a test asserting the id (`data-mascot`) on that surface.
